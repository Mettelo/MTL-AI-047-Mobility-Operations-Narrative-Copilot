# Mandatory team repository standard

## Ownership and access
Use one repository named `MTL-AI-047-<team-name>`. Prefer creating it inside the Mettelo GitHub organisation where authorised.

Every delivery must have verified Mettelo review access before submission. A personal repository cannot generally invite an entire organisation as a collaborator. For a repository outside Mettelo, follow the cohort's designated transfer or named reviewer/team access route; do not invent an account or assume public visibility alone meets the cohort process.

The team lead records the repository owner, designated reviewer/access route, verification date and evidence. Reviewers need to inspect files, commits, branches, issues, PRs, tests, documentation and contribution records. Keep access active until sign-off. This pack does not itself grant permissions or transfer repositories.

## Collaboration
Use individual GitHub accounts. Track material work in issues; use branches and reviewed PRs for substantial changes, especially KPIs, prompts, verification and approval logic. Make meaningful commits throughout delivery. Do not upload an entire team's project in a single final commit.

Maintain CONTRIBUTIONS.md with member, role, issue/PR/commit links, artifact and peer-review evidence. Combined roles are allowed; fabricated contributions are not.

## Reproduction and security
Provide tested setup/run/test/evaluation/export instructions, exact tested dependencies, source acquisition and checksums, model digest and local installation route. Never commit passwords, tokens, private personal data or model weights. Optional hosted services cannot be required to reproduce the core flow.

## Completion
Complete final submission, verify access, pass acceptance checks and identify the immutable evaluated commit and submission tag. Official submission is the team repository URL; keep review evidence accessible through assessment.
