# Team roles and stage ownership

| Role | Accountable work | Evidence |
|---|---|---|
| Team lead / product owner | Scope, issue board, dates, access, handover and final submission | Decisions, review links and access verification |
| Data engineer | Acquisition, manifests, validation, immutable raw data | Downloader, validation report and provenance |
| Analytics engineer | KPI definitions, windows, exposure and reconciliation | Formula code, independent checks and tests |
| AI engineer | Local runner/model, evidence prompts, structured drafts and repair policy | Model/prompt manifests and local runs |
| Application engineer | Review UI, evidence navigation, revisions and export | Working journey and state tests |
| QA / evaluation lead | Gold cases, holdout freeze, corruption tests, scoring and UAT | Evaluation results and failure log |
| Analyst reviewer | Interpretability, caveats, human sign-off | Reviewed examples and UAT decisions |

Combine roles to match team size; record names, responsibilities and backup reviewer. Every member uses their own account and contributes identifiable work. A separate person checks calculations and material AI/control changes where practical.

Suggested stage exits: scope approved → data/KPIs reconciled → local draft/verifier demonstrated → review/export working → benchmark/UAT passed → tagged handover. Assign issue owners and dates; do not mark a stage done on documentation alone.
