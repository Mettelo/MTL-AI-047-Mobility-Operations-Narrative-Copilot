# Technical handover requirements

The team handover must document real entry points and tested commands for environment setup, source acquisition/hash checks, validation, KPIs, evidence, baseline, local generation, verification, review/export, tests and evaluation.

Include module architecture and contracts; formula/policy versions; model installation/digest/licence; prompt/schema versions; hardware and runtime; report state transitions; storage/logging layout; known faults and troubleshooting. Explain recovery from missing model, invalid source hash, coverage failure, malformed output, failed claims and stale approval. Never recommend bypassing a verifier to finish a demo.

A second person follows the instructions from a clean checkout and records date, platform, versions, results and unresolved issues. Commit small attributed sample bundles and raw benchmark results. Identify rebuildable files and how to regenerate them, how to remove local draft logs, and what remains unsupported for production use.
